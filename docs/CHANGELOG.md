# 更新记录

## 2026-09-23：可见审查唤醒与 Desktop 协议兼容修复

本次整理基于已有的本地改动，保持 `0.1.0.dev0` 的 pre-alpha 定位；不代表稳定版发布。

### 修复

- 通用 `loopweave submit --stage/--final` 接入可见审查调度。绑定可见审查的
  Agent 正式提交后会请求唤醒审查任务，不再依赖 Claude Stop Hook 补做唤醒。
  调度失败时保留唯一待审卡及 `ready_for_review` 状态，并记录错误；不会静默丢卡。
- Codex Desktop IPC 优先发送 v2 请求格式。只有明确收到 `no-client-found`
  才回退 v1；连接中断、读超时及 `request-timeout` 不会触发自动重放，避免重复请求。
  默认等待时间从 8 秒调整为 15 秒，为桌面端查找接收客户端留出时间。

### 审查边界与文档

- 允许绑定的主审使用只读取证助手执行测试、静态检查或收集其他证据。助手无权修改
  被审工作区、操作 Run、推进任务包或提交裁决；主审必须独立核验并亲自提交唯一裁决。
  公开提示不绑定任何个人自定义 Agent 名称。
- 命令参考明确 `design` 模式最多 2 轮审查，多阶段开发使用 `develop` 模式。
- 更正架构文档中运行数据默认依附源码目录的过时说明；运行根目录已与源码分离。

### 验证范围与限制

- 新增或扩充通用提交唤醒、失败保留、Hook 不重复调度、IPC v2/v1 兼容、
  不确定结果不重放，以及只读取证助手权限边界的回归测试。
- IPC 协议测试使用本地模拟服务；当前 Codex Desktop 版本的真实可见唤醒验收
  仍待完成。`bridge doctor` 只验证 initialize 握手，不能代替真实唤醒验收。
- 本次没有加入 Windows ConPTY 支持，也没有合并其他分支或 PR。
